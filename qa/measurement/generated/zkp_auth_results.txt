  PROTOCOL (all four groups):
    Prove:  R = r·G,  c = SHA-256(Y ‖ R),  s = r − c·x  (mod q)
    Verify: s·G + c·Y == R  (in group)
  MODP-2048 uses multiplicative group notation: R = g^r mod p
  P-256 uses ECDSA which is Schnorr-family (sign=prove, verify=verify).

  Implementation basis:
    MODP-2048    Python built-in  pow(base, exp, mod)  — optimized C bigint
    P-256        cryptography library (OpenSSL bindings) — near-native C speed
    bn128-G1     py_ecc 8.0.0 — pure Python EC arithmetic (~1.7 ms/scalar-mul)
    bls12-381-G1 py_ecc 8.0.0 — pure Python EC arithmetic (~3.0 ms/scalar-mul)

  NOTES:
  bn128 security: ~100 classical bits (Kim-Barbulescu attack on pairing curves).
  All four groups are broken by Shor's quantum algorithm — not quantum-safe.

  IMPLEMENTATION BIAS:
  P-256 uses native OpenSSL — orders of magnitude faster than pure Python.
  MODP-2048 uses Python's C-backed pow(b,e,m) — competitive for large modulus.
  bn128/bls12-381 use py_ecc (pure Python) — expected ~50-100x slower than liboqs/C.
  With native C (e.g. libsecp256k1, blst): bn128 ≈ 0.05 ms, bls12-381 ≈ 0.1 ms.

  ABOUT zk-STARKs vs Schnorr:
  Schnorr PoK proves "I know x such that Y = x·G" (single scalar, linear relation).
  zk-STARKs (FRI-based) prove arbitrary computations; overhead: ~10,000–1,000,000x.
  No pure-Python zk-STARK library is available on PyPI for Python 3.12 (2026-06).
  Benchmarking zk-STARK auth would require Cairo (StarkWare) or Circom + snarkjs.
